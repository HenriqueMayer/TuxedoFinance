A local application to record income and expenses, track accounts and card bills, and organize investments.

Access links depend on authentication and signup policy. Six feature rows follow the introduction. No sample balances, promotional cards, or repeated call to action.

Section 4

Forms.

Same field contract as the app (label, contextual help, errors). Inputs keep generous rounding with forest borders and caramel focus; labels use sentence case at 14px. Disabled controls preserve their native semantics.

Mandatory keyboard and conditional-choice contract

Tab / Shift+Tab move between controls. Record searches use ↑/↓ and Enter; Escape cancels. Checkboxes use Space; advanced summaries use Enter or Space.

Reaching or opening a record search brings its input and results into view without moving focus. Long lists scroll internally and fit below the sticky header, including on short mobile screens.

New conditional choices start empty. Reveal credit-card details only after a card is confirmed; retain edited values and server errors. Use the shared component for all record selectors.

6.4 — Question-mark help and chart tooltips

All question-mark icons use the shared help contract: hover or keyboard focus opens one box; leaving the icon and text, clicking outside or Escape closes it. Mouse clicks never pin help. Touch toggles; no JavaScript retains native disclosure.

Layout & spacing.

Workspace width
max-w-7xl mx-auto; px-4 sm:px-6 lg:px-8. Use space-y-6 or space-y-8 between sections.
Cards establish reading groups
Use surface-panel for a bank, chart, input stage or result, and metric-panel for comparable summaries. Keep rows within the group separated by dividers; avoid nesting one card inside another.
Lists and categories
Keep parent and child rows together. Show type and direct usage, then contextual edit actions. Import, export and destructive actions belong in secondary options.
Tables and simulation
Use semantic headers, tabular numeric columns and labelled horizontal scrolling regions. Bank account rows become labelled groups below 768px; planning sheets scroll inside their own region. Change result regions without replacing a focused input. Month overrides are empty until deliberately filled.
Forms
Single-column entry forms use a readable width; related simulation inputs may share rows. Reuse the shared field and choice controls. Keep server errors next to inputs and preserve native submission.

Section 8

Motion.

Durations inherited from Haven & Hound: 300ms for colors/shadows/opacity, 300ms for the mobile overlay, 700ms reserved for the public homepage image zoom. No custom keyframes. Everything below is interactive.

Application navigation does not fade the whole interface. HTMX keeps the current server-rendered document visible until the next body is ready, then swaps it immediately; native links remain the no-JavaScript fallback.
