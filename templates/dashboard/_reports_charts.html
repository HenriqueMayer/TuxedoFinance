{% load l10n %} {% comment %} Partial rendered in two ways (see `dashboard.views.DashboardReportsView`): 1. As the body of `dashboard/reports.html` for a normal page load — the page wrapper (`
`, the header, the navbar from `base.html`) lives around it. 2. Standalone, when the request carries `HX-Request: true` — the view returns only this template so HTMX's `outerHTML` swap can replace the matching `
` in the page with the new one from the response. Returning a full HTML document instead would confuse the swap (HTMX would inline the response body inside the target, duplicating the navbar and the outer wrapper every click — the exact bug this split fixes). Every interactive control in this partial carries `hx-get` / `hx-target="#reports-charts"` / `hx-push-url="true"`, plus a plain `href` / `action` as the no-JS fallback. With HTMX loaded the swap goes through and the URL updates without a full page load; without it the same link is a normal GET that renders the full reports page. Charts 3 and 4 are stacked vertically on every screen width — the shared `?payment_month=ALL|YYYY-MM` filter sits next to the title of each, and clicking a bar still opens its own drill-down panel (`?expense_method=` for chart 3, `?income_method=` for chart 4) below the chart. Chart 5 ("Where the money goes") comes last so the two-click drill-downs above are not interrupted by a tall list of categories. Design tokens (PRD §9.1): the `tone` values coming out of charts.py are mapped to Tailwind classes here so the design system stays in the template layer; the only literal color values are inside SVG stops for the primary indigo→fuchsia stroke (Tailwind utility classes do not apply to SVG stroke attributes). See the docstring at the top of `dashboard/reports.html` for the broader conventions this partial inherits. {% endcomment %}
