{% extends 'base.html' %} {% load l10n %} {% comment %} Investments (parallel universe to `Transaction`). Shows only the logged-in user's own entries (`InvestmentListView.get_queryset`), paginated, each row color-coded by `kind` (Deposit emerald / Withdrawal rose) per the design system's semantic colors already used on the transactions list. The card grid at the top is per-currency, not per-type: one card per supported currency (base first, then alphabetical), each showing that currency's deposited / withdrawn / net balance, plus a "simulated total in {base}" card that adds everything up at the user's latest `ExchangeRate` for each foreign currency. Currencies without a rate are excluded from the simulation and the card surfaces that explicitly so a missing rate can never silently shrink the displayed total. Optional filters: `?kind=DEPOSIT|WITHDRAWAL` narrows the table, `?q=` searches title / reason / notes. Pagination uses `{% querystring %}` so the active filters survive page navigation. At the bottom of the page (after the list / pagination), two chart sections sit there: 1. **Investment evolution** — area-and-line chart of the cumulative portfolio total in the base currency, converted through the exchange rate that was current at each month's close. Slidable through time via `?total_offset=N`. 2. **Monthly flow** — grouped bars of Deposits × Withdrawals per month, both in the base currency. Slidable through time via `?flow_offset=N`. Each chart section is rendered via an `{% include %}` of the `_investments_charts.html` partial, which is also the HTMX swap target when the prev/next arrows are clicked (the view returns only the partial when `HX-Request: true`). The section is hidden via `{% if has_investments %}` — flat-at-zero lines and bars are not informative, and the empty-state CTA above already tells the user to add an entry.
